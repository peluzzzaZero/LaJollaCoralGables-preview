# Review: v1.13.0

Review scope: native inquiry preparation, hosted MySQL, optional private mail setup and same-origin form transport. Public sending defaults off; adding credentials alone does not enable delivery. Preview and live share GoDaddy's database, so initialization creates only `lajolla_preview_v1_*` or `lajolla_live_v1_*` tables. A strict namespace allowlist and parameterized data queries prevent request input from selecting SQL objects. No unrelated table migration is performed.

Inspect storage-before-send, transaction-protected rate counting, conditional delivery claims, identity conflicts and uncertain response handling. MySQL tests use an isolated local/CI MySQL 8.4 database with fake credentials and providers. Review encrypted vault persistence and wrong-key rejection. The private setup must gate all mutations and technical mail with a setup password, owner cookie, exact Origin and CSRF; OAuth callbacks also require a single-use, cookie-bound state and PKCE challenge. Provider acceptance differs from manually confirmed inbox receipt.

Microsoft authorization verifies signed issuer/audience/expiry/nonce/tenant and Graph's account id and business mailbox before storing credentials; refreshes recheck the account and never fall back to app-wide credentials. GoDaddy omits `from`, obtains its business recipient from private runtime configuration and never accepts caller recipients. Gateway errors remain generic and uncertain attempts require review.

Native transport is injected only by the Node server into planning.html; both forms use `/api/inquiries` with a UUID and no third-party keys. Static Pages stays compatible. Failed fields and manual drafts remain available; no contact details are stored in browser storage. Success does not confirm appointments or spaces. Review native browser retries, uncertain reference translation, quote/vendor mapping and absence of external mail calls.

This review does not certify live authorization, actual receipt, hosted persistence, calendar access, quotas or production-domain migration. Those require evidence from the business account and its actual deployment.
