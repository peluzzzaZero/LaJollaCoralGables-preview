# v1.22.0 — reviews, location and a quiet credit

The owner was pleased with the mobile scenes of v1.21.0 and asked for three things: the entrance film and its frame on desktop were not quite right, guest reviews and opinions should be integrated together with the location, and a discreet gray "powered by peluzzza" should sit at the very bottom of the page.

1. Desktop entrance — the header is opaque on the landing, so from 651 px (tablet and desktop) the film, its shade and the thin frame now start below it. Before, the top 76 px of the approach film and the frame's top edge were hidden behind the header, so the frame looked open at the top. The frame, the arch scene and the arrival phrases keep their scroll behaviour; mobile is unchanged.
2. Reviews and location — a new chapter between the team and the invitation ("Reviews & location" / "Opiniones y ubicación", also in the header navigation). The existing Google reviews component moves here from the occasions chapter. Until the owner's restricted browser key exists it shows an invitation card with links to read the reviews on the Google Maps listing and to write one (place ID ChIJWbeTzJu32YgRbGDUdwzI0W0). No testimonial, star count or aggregate rating is written into the page; with a key, the component still shows only selected five-star reviews with Google attribution. Beside it: the address (301 Alcazar Avenue, Coral Gables, Florida), phone, email, Google directions, Apple Maps and a Google map that is a keyless embed created only after the visitor presses "Show the map". Until then the approved facade photograph stands in and no third-party request is made.
3. Credit — "powered by peluzzza" in 10 px gray type, centered under the copyright line of the footer, identical in both languages and excluded from translation.

Also in this release (merged to develop separately in #77): the six-tile mosaic that shipped in v1.21.0 is now generated from `assets/social/tiles.json` with `python scripts/social-tiles.py` (6 or 12 tiles; owner originals stay git-ignored; post tiles need a recorded post approval and EN/ES labels; CI runs `--check`). The published tiles are unchanged.

No new video, generated media, scripts or trackers. The browser test intercepts the map request and the Places SDK; no real Google call is made in CI.

Release gate (results recorded in the feature and release pull requests): the static/content suite, the browser review in EN and ES at every reviewed width including the new chapter and footer, real Chromium/WebKit entrance decoding, landing fallbacks, desktop anchors and the mocked reviews/map cases. Exact-head external review, successful CI and visual inspection are required before each merge. Known limitations: the cloud review environment cannot reach google.com, so the embedded map itself was verified with an intercepted page rather than the live Google map; the credit's light gray is intentionally quieter than body text (about 3.7:1).

Next useful improvements: the owner's restricted Google browser key (Maps JavaScript API + Places API (New)) saved as the GOOGLE_MAPS_BROWSER_KEY Actions variable so selected reviews appear on the page, owner-chosen Instagram posts for the mosaic, and device testing on older iOS Safari.
