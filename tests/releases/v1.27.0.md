# v1.27.0 — the map you can see, and reviews that appear

The owner reported that Google Maps still was not visible in the Location chapter ("In the heart of Coral Gables"): it showed the facade photograph with an "Open in Google Maps" button. He asked for the map to be fixed on the house's location and visible, and for a section with the best Google reviews.

1. Visible map — the facade photograph gives way to an embedded Google map (`maps.google.com/maps?q=301+Alcazar+Ave, Coral Gables, FL 33134&z=16&output=embed`), lazy-loaded as the visitor approaches and slightly desaturated toward the beige palette. v1.22's embed searched "La Jolla, 301 Alcazar Avenue…" and fell back to a world view (the name also matches La Jolla, California); this one queries only the full street address with ZIP. The map follows the page language. "Open in Google Maps" sits just below it, clear of Google's own map controls, and opens the official Maps URL with La Jolla's Place ID (ChIJWbeTzJu32YgRbGDUdwzI0W0) in a new tab. "Get directions" and "Open in Apple Maps" are unchanged.
2. Reviews that appear — with the restricted Google browser key configured, selected five-star Google reviews now load on their own as the visitor nears "Guest experiences", without the former "See selected guest reviews" button. Same rules as before: five stars only, original text, author and date with links to Google, Google attribution, no aggregate rating, nothing invented or stored. Without the key the Google invitation card (read and write reviews on Google Maps) remains, and nothing from Google loads for reviews.
3. Guest words, always visible — five short excerpts of real five-star Google reviews the owner supplied (first name and initial, occasion), in a light swipeable row of cards above the Google invitation, noted as excerpts from the Google listing. Text only, no screenshots; cuts are marked with an ellipsis. Once Google's own reviews load, they replace the excerpts. Source, owner approval and each excerpt are recorded in `tests/REVIEW-EXCERPTS.md`; the terms page describes the excerpts.
4. Privacy — the privacy page now says the Location section embeds a Google map that loads from Google when the visitor scrolls near it, and that configured reviews load the same way.

No new video, generated media or trackers. No banned wording, prices or capacity.

Verification: static suite (the map frame must query the full address with ZIP, be lazy and translated, and be the page's only map frame; the Place ID button remains), browser review with Google intercepted in Chromium (WebKit in CI): no Google request before scrolling, map fills its frame and loads on approach, the button takes taps and opens Google Maps in a new tab, reviews appear without a click; an external Sonnet/high review of the exact head and mobile and desktop screenshots in EN and ES, recorded in the feature and release pull requests.

Live map: an informational CI step (`tests/browser/map-live.py`) opens the real embed in an iframe from GitHub's runners. On commit b7f32c7 (workflow run 38719414120) Google rendered the place card "301 Alcazar Ave, Coral Gables, FL 33134, USA" with the pin at number 301 on Alcazar Avenue, between Le Jeune Road and Galiano Street. Limitations: this development environment cannot reach Google, so the local browser tests stub the map; a check on a real phone after publication is still advisable. The keyless embed is not Google's documented Embed API; once the browser key exists, the documented Maps Embed API by Place ID is the stricter option. Loading reviews on approach means one Places request per visitor who reaches the section; set a budget alert in Google Cloud. Reviews stay invisible until the owner activates the key (Maps JavaScript API and Places API (New), billing, key restricted to lajollacoralgables.com, GitHub Actions variable `GOOGLE_MAPS_BROWSER_KEY`).

Next useful improvement: activate the browser key and confirm map and reviews on a real phone.
