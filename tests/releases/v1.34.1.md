# v1.34.1 — "Good to know" links to the tour calendar

On 29 October 2026 Dan asked, from a phone screenshot of the tour's "Good to know" card, whether that part could carry a link to book the tour.

1. The first line of the card keeps its words. Its second half, "choose an available time in the calendar" ("elija un horario disponible en el calendario"), is now a text link in the card's own type and the brand sage, underlined. It opens the same Microsoft Bookings calendar in the site's booking dialog that the seal's calendar fallback uses; with modifier keys or without JavaScript it is an ordinary link to the Bookings page in a new tab.
2. It is a link inside a sentence, not a button: the landing keeps its single "Schedule a visit" (the seal, which opens the assistant). The link does not carry `data-booking-opener`, so the one-button tests still count one opener; it uses `data-calendar-link`, which the booking dialog code also handles. Because the sentence promises the calendar, the link opens the calendar directly rather than the assistant.
3. `tests/tour.test.mjs` checks the single text link, its EN/ES copy, the handler and the style.

Verification for this release: `npm run build && npm test`; local Chromium screenshots of the card and of the booking dialog opened from the link (Bookings stubbed) at 390 and 1440 px, EN/ES, plus 884 px; external review (Claude CLI, Sonnet/high) of the PR head, with findings and resolutions on the pull request.

Limitations: the Bookings page cannot load from the build environment (stubbed in tests); no real booking was made.
