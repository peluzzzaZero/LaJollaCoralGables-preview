# v1.29.2 — arrows that never turn into emoji

The owners reported, with an iPhone (Safari) screenshot, that the arrows on the Instagram, TikTok and Pinterest cards appeared as blue emoji tiles. iOS gives "↗" (U+2197) emoji presentation when the page font has no glyph for it, so the same character looked like a thin arrow on desktop and like an emoji on the phone.

Version: 1.29.1 is reserved for the parallel review-excerpt patch on its own feature branch; this patch takes the next free number.

1. Social cards and "See more on Instagram": the "↗" character is replaced by an inline SVG arrow (`.icon-arrow`: 12×12 viewBox, `stroke: currentColor`, 1.25 stroke, no fill), hidden from assistive technology; `fill`/`stroke` are also set on the path so the icon is right before the stylesheet loads.
2. "Discover the house" in the arrival: the "↓" character is replaced by the same drawn icon pointing down.
3. "Schedule a visit" on the occasions and "Let's imagine your occasion here": their `.link-arrow` was already drawn with CSS borders; the hidden "↗" text inside it is removed so no arrow character remains in the page.
4. The unused `cinema.continue` strings (EN/ES) no longer end in "↓".

No copy, links or layout changes; colour follows each link's text colour.

Tests: new `tests/arrows.test.mjs` fails if `index.html`, `planning.html`, `privacy.html`, `terms.html`, `script.js`, `social.js` or `styles.css` (comments excluded) contain arrows (U+2190–21FF, U+27F0–27FF, U+2900–297F, U+2B00–2BFF), geometric shapes, dingbats and symbols (U+25A0–25FF, U+2300–23FF, U+2600–27BF except the review star U+2605, plus ‼ ⁉ ™ ℹ Ⓜ 〰 〽 ㊗ ㊙), the emoji variation selector U+FE0F, keycaps or any emoji plane character; it also checks that `.link-arrow` spans are empty and that the arrow icons are the drawn SVG in `currentColor`. `tests/social.test.mjs` expects the SVG in each social card.

Verification before the release pull request: `npm test` (150 passing). Local Chromium screenshots at 390 px (mobile emulation) and 1440 px in EN/ES of the social cards, Instagram handle, occasion link, arrival hint and venue invitation, compared with the owners' iPhone screenshot; mobile WebKit runs in CI.

Review evidence (model, effort, exact head, findings and resolutions) is recorded in the feature pull request and its release pull request, not in this file.

Limitations: no real-iPhone check was possible from the build environment; the WebKit used in CI does not ship Apple's emoji font, so the definitive check is on an iPhone after publication.

Next useful improvement: confirm on the owners' iPhone after publication.
