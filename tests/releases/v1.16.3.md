# v1.16.3 — responsive closing contact and focused video scrubbing

The footer now closes the cinematic homepage in the same forest palette. Brand, contact and location have three compact zones; legal links sit in the bottom strip. It removes the duplicated address and misleading Connect heading, wraps long links, and adjusts across phone/tablet/desktop widths including 884px.

Video seeks are restricted to the active clip and the two clips participating in a dissolve. Hidden clips stop chasing scroll positions. Preloading anticipates both forward and reverse travel; returning to a dormant clip keeps its poster until the requested frame settles. The poster covers a renderable video instead of hiding the decoder with opacity zero. Mobile decoder priming now starts only when the clip is visible, records success only after decoding, and retries a rejected or delayed start up to three times. If WebKit stalls before blob metadata, it falls back once to the native URL/range loader for the same approved clip. Existing approved media, the nine chapters and Microsoft Bookings remain in use.

Delivery now follows feature → develop → main, with external Claude CLI Sonnet/high review, and explicitly documented Sol/medium fallback only after an actual CLI failure. Release checks include responsive footer geometry and rapid reverse seek regression tests.

Reference inspected: midudev/mcp-higgsfield-landing at da1bbe693ef1939794662e96c0ba6571e9c3f418, especially src/scripts/world.ts. The implementation retains the existing vanilla JS/GSAP stack. No video was generated. Existing independently photographed scenes cannot become a frame-identical continuous camera take through code alone.

Validation and reviewer provenance are recorded on the feature/release PRs for the exact reviewed commit. No real emails or bookings are submitted by automated checks. Mobile WebKit emulation complements, but does not replace, real-device testing.
