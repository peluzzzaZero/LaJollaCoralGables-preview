# v1.31.1 — visit times in Florida time, one address everywhere

On 26 October 2026 the owner reported a problem with tour times: a "new appointment" notification for a Private Venue Tour read `Start: 10/27/2026 17:30:00`, `End: 10/27/2026 18:15:00`. The business and its visitors are in Coral Gables, Florida (America/New_York: EDT until 1 November 2026, EST after).

Most likely cause (inferred; the flows cannot be opened from the build environment, so it awaits confirmation in the flow's run history): that notification is not written by this site. It comes from one of the owner's Power Automate flows, which appears to print the appointment's start and end exactly as the Bookings connector delivers them, in UTC. 17:30–18:15 UTC is 1:30–2:15 PM EDT, a normal 45-minute tour. The site change below is a mitigation; the owner-side settings are the real fix. The site never handles appointment times; it opens the owner's Bookings page, whose calendar can show times in the visitor's own time zone.

1. The booking dialog's help text (EN/ES, on every page) now names the place and the time zone: tours are at 301 Alcazar Avenue, Coral Gables, FL 33134; times are Florida time (Eastern Time), and a visitor whose calendar shows another time zone is told to choose Eastern Time before booking. It replaces the generic "Check the time zone shown before booking."
2. The footer "Find us" links on the landing and planning pages open Google Maps with the full address and the venue's Place ID (as the location card already did), instead of the bare "301 Alcazar Avenue, Coral Gables"; the location card's Google and Apple Maps links gain the ZIP, so every Maps link uses the same address. On short landscape phones (height ≤ 520 px) the dialog's header, help and fallback lines are tighter so the calendar stays the largest part.
3. The JSON-LD address gains `postalCode` 33134.
4. `tests/booking-time.test.mjs` checks the help text in both languages and on every page, the footer map links and the postal code.

Owner-side settings (Microsoft 365, not in this repository): in each Power Automate Bookings flow, format start/end with `convertFromUtc(triggerOutputs()?['body/startTime'], 'Eastern Standard Time', 'MM/dd/yyyy h:mm tt')` (and `endTime`); in Bookings, set the business time zone to Eastern Time and the address to 301 Alcazar Ave, Coral Gables, FL 33134, and turn on "Always show time slots in business time zone" on the booking page.

Verification for this release: `npm run build && npm test`; external review (Claude CLI, Sonnet/high) of each PR head, whose findings and resolutions are recorded on the pull request rather than here; local Chromium screenshots of the open booking dialog at 320, 390, 768, 884, 901 and 1440 px and short landscape 568×320 and 667×375, EN/ES (the Microsoft frame itself cannot load from the build environment). CI runs the browser suites, including WebKit.

Limitations: the Bookings page, its emails and the Power Automate flows cannot be reached or changed from the build environment; no real booking was made.
